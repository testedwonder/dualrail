## Principles

- The reader, notes, ratings, research registry, and core labs remain free.
- Support is voluntary and never changes source credibility or learning access.
- No payment provider script loads until the user deliberately opens a support link.
- The application does not collect payment credentials or financial account data.
- Sponsorship never buys a scientific claim, verification mark, or content ranking.

## Before enabling support

1. Keep the public author and support destinations current.
2. Publish a short funding disclosure if the use of support becomes more specific.
3. Confirm tax, platform, trademark, privacy, and regional obligations.
4. Test every destination before each release on desktop and mobile.

## Planned interface

The report flow now contains an **After reporting** support prompt. An **About the author** control can be added after the same verified metadata is supplied. The interface may contain:

- author credit and a concise portfolio;
- project role and contribution boundaries;
- one public portfolio link;
- optional support buttons with provider names and external-link indicators;
- a statement that support is voluntary and does not unlock content.

Do not add placeholder payment URLs. A missing provider is omitted. Public overrides are listed in `app/.env.example`; they must never contain credentials.

## Verification checklist

- Links match the author's verified accounts exactly.
- External destinations open in a new tab and are visibly labeled.
- The free core works when every funding link is disabled.
- No analytics or third-party payment script runs automatically.
- Automated tests cover absent, single-provider, and multiple-provider states.
- The public privacy and licensing documentation names the final arrangement.
